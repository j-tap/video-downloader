# video-downloader

Веб-приложение для скачивания видео через `yt-dlp` с простым UI и API.

## Требования

- [Bun](https://bun.sh)
- `yt-dlp` в `PATH` (или переменная `YTDLP_PATH`), установленный с расширением
  `default`: `pip install "yt-dlp[default,curl-cffi]"`. Оно приносит `yt-dlp-ejs`,
  без которого YouTube отдаёт неполный набор форматов
- JS-рантайм для `yt-dlp-ejs` — [Deno](https://deno.land) (приоритетный),
  Node.js, Bun или QuickJS. В Docker-образе ставится Deno
- `ffmpeg` (для merge/remux в mp4)

## Установка

```bash
bun install
```

## Запуск

```bash
cp .env.template .env
bun run dev
```

По умолчанию сервер стартует на `http://localhost:3000`.

## Поддерживаемые источники

- YouTube (`youtube.com`, `youtu.be`, `youtube-nocookie.com`)
- Facebook (`facebook.com`, `fb.com`, `fb.watch`)
- Instagram (`instagram.com`, `instagr.am`)
- kino.pub и её CDN `cdntogo.net` (обычно требует авторизацию через cookies)
- TikTok (`tiktok.com`, короткие `vm.tiktok.com`, `vt.tiktok.com`)
- VK (`vk.com`, `vk.ru`, `vkvideo.ru`)
- Rutube (`rutube.ru`)

Другие сайты отклоняются: сервис публичный, и открытый список хостов
превращает его в прокси во внутреннюю сеть. Список расширяется через
`ALLOWED_HOSTS` — см. [Безопасность](#безопасность).

## Формат готового файла

По умолчанию выбирается H.264 + AAC — такой mp4 открывается везде: QuickTime,
Safari, телевизоры, видеоредакторы. Плата за это — потолок 1080p на YouTube:
4K там раздаётся только в AV1 со звуком Opus, а это уже не совместимый mp4
(расширение mp4, но у многих плееров такой файл идёт без звука или не
открывается вовсе).

Кому важнее разрешение, а не совместимость:

```bash
VIDEO_FORMAT=bv*+ba/b
```

Instagram и Facebook перекодируются в H.264/AAC всегда — там исходные потоки
слишком разношёрстные.

## PO Token для YouTube

YouTube выдаёт качественные дорожки серверным адресам только вместе с PO Token.
Без него типичный результат с VPS — `HTTP 403` либо единственная дорожка 360p
(видео «скачалось», но смотреть его нельзя).

`docker-compose.prod.yml` поднимает провайдер токенов
([bgutil](https://github.com/Brainicism/bgutil-ytdlp-pot-provider)) отдельным
контейнером во внутренней сети и передаёт приложению `POT_PROVIDER_BASE_URL`.
Аккаунт для этого не нужен — это надёжнее cookies: экспортированную сессию
браузера YouTube регулярно инвалидирует при использовании с чужого IP,
а сам аккаунт при этом рискует получить бан.

Провайдер необязателен: если контейнер не поднят, `yt-dlp` ограничится
предупреждением, а приложение напишет об этом в лог при старте. Cookies при
этом продолжают работать и остаются нужны для приватных и возрастных видео.

## Выход для YouTube

С адреса хостинга YouTube на любое видео отвечает «Sign in to confirm you're
not a bot». Это блокировка адреса: PO Token, cookies и другие клиенты YouTube
её не снимают, а с домашнего IP та же ссылка качается. Помогает только чужой
выход — VPN, Cloudflare WARP или резидентный прокси.

На сервере выход общий: VPN (gluetun + Mullvad) из проекта vr-nine. Он подключён
к внутренней сети `vpn-egress` под именем `vpn-proxy`, и в этой сети только
прокси и те, кто им пользуется. Браузер и сайт vr-nine остаются в своей сети.
`make prod` создаёт сеть, если её ещё нет, и подключает к ней сервис. По
умолчанию в `docker-compose.prod.yml`:

```bash
YT_PROXY=http://vpn-proxy:8888,direct
```

Через прокси идёт только YouTube, остальные площадки качаются напрямую.
Выходы пробуются по порядку: если прокси не отвечает или YouTube не пускает
его адрес, берётся следующий. `direct` — с адреса сервера, на случай если VPN
не поднят. Запасной выход дописывается через запятую:

```bash
YT_PROXY=http://vpn-proxy:8888,socks5://warp:1080,direct
```

Строка `Proxy YouTube:` в логе при старте показывает, через что идёт YouTube.
Если YouTube перестал пускать и адрес Mullvad, в логе будет «YouTube не пустил
ни один выход» — смените сервер Mullvad в vr-nine (`MULLVAD_SERVER`).

## Cookies и авторизация

Приложение умеет подбирать cookies по домену, чтобы не смешивать сессии разных сайтов.

### YouTube

- `YT_COOKIES_FILE` или `data/cookiesYoutube.txt`
- `YT_COOKIES_FROM_BROWSER` (например `chrome`)
- Для обычных публичных видео cookies не нужны — эту задачу решает
  [PO Token](#po-token-для-youtube). Оставьте их для приватных, возрастных
  и доступных только по подписке видео
- Экспортируйте cookies из окна инкогнито и не заходите в этот аккаунт
  из браузера после экспорта: иначе YouTube ротирует сессию и файл протухает

### kino.pub

- `KINOPUB_COOKIES_FILE` или `data/cookiesKinoPub.txt`
- `KINOPUB_COOKIES_FROM_BROWSER` (например `chrome`)
- Если страница `item/view/...` отдает только трейлер, используй прямую `m3u8` ссылку full-видео из Network в браузере

### Общий fallback

- `COOKIES_FILE` или `data/cookies.txt`
- `COOKIES_FROM_BROWSER`

Общий файл подставляется только к известной площадке, у которой нет своего.
Хост вне списка площадок не получает cookies вообще.

### Instagram / Facebook

- `INSTAGRAM_COOKIES_FILE` / `INSTAGRAM_COOKIES_FROM_BROWSER`
- `FACEBOOK_COOKIES_FILE` / `FACEBOOK_COOKIES_FROM_BROWSER`
- Для ссылок Instagram/Facebook автоматически убираются трекинг-параметры (`utm_*`, `igsh` и т.п.)

### TikTok / VK / Rutube

- `TIKTOK_COOKIES_FILE` / `TIKTOK_COOKIES_FROM_BROWSER` (или `data/cookiesTiktok.txt`)
- `VK_COOKIES_FILE` / `VK_COOKIES_FROM_BROWSER` (или `data/cookiesVk.txt`)
- `RUTUBE_COOKIES_FILE` / `RUTUBE_COOKIES_FROM_BROWSER` (или `data/cookiesRutube.txt`)
- Открытые ролики качаются без cookies. TikTok закрыт для части стран: если
  он отвечает адресу сервера `403`, пустите его через VPN (`TIKTOK_PROXY`)

Все cookie-файлы должны быть в формате Netscape.

## Полезные переменные окружения

- `PORT` — порт сервера (по умолчанию `3000`)
- `PROXY` — выход для всех площадок; `YT_PROXY`, `INSTAGRAM_PROXY`,
  `FACEBOOK_PROXY`, `KINOPUB_PROXY`, `TIKTOK_PROXY`, `VK_PROXY`,
  `RUTUBE_PROXY` — для одной площадки, перекрывают `PROXY`.
  Список через запятую пробуется по порядку, `direct` — без прокси
  (см. [Выход для YouTube](#выход-для-youtube))
- `VPN_EGRESS_NETWORK` — имя общей сети с VPN (по умолчанию `vpn-egress`)
- `YTDLP_PATH` — путь к бинарнику `yt-dlp`
- `YTDLP_CHANNEL` — канал `yt-dlp` при сборке образа: `nightly` (по умолчанию,
  починки экстракторов приходят в тот же день) или `stable`
- `VIDEO_FORMAT` — селектор форматов `yt-dlp` (по умолчанию H.264 + AAC)
- `POT_PROVIDER_BASE_URL` — адрес провайдера PO Token
- `YT_PO_TOKEN` — токен YouTube, добытый вручную (альтернатива провайдеру)
- `YT_PLAYER_CLIENT` — ручной выбор `player_client` для YouTube

В Docker переменные приезжают в контейнер из `.env` через `env_file`,
поэтому менять их можно без пересборки образа — достаточно `make restart`.

## API сайта

- `POST /download` — старт загрузки (`{ "url": "..." }`)
- `GET /status/:id` — статус загрузки
- `POST /cancel/:id` — отмена загрузки
- `GET /file/:id` — скачать готовый файл

Сервис публичный, но загрузка привязана к клиенту: `/status`, `/file` и `/cancel`
доступны только тому браузеру, который её запустил (cookie `vd_client`).

## API для серверов (`/api/v1`)

Второй вход — для серверов, которые забирают ролик к себе (первый клиент —
Todi). Договор с ним — `docs/video-links.md` в репозитории childs-games:
коды ошибок, поля ответа и пределы меняются только вместе с ним.

Ключ — заголовок `Authorization: Bearer <секрет>`. Ключи именованные:

```bash
API_KEYS=todi:$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '=')
```

Пустой `API_KEYS` — весь `/api/v1` отвечает `401`, сайт работает как раньше.
Отозванный ключ переносится в `API_KEYS_REVOKED` и получает `403`.

| Запрос | Что делает |
| --- | --- |
| `POST /api/v1/jobs` | Поставить скачивание: `{ url, maxDurationSec, maxBytes, maxHeight }` → `202 { id, status }`. `Idempotency-Key` — повтор в течение суток возвращает ту же задачу |
| `GET /api/v1/jobs/:id` | Состояние: `queued`, `downloading`, `processing`, `ready`, `failed`, `cancelled`, метаданные, `sha256`, `expiresAt` |
| `GET /api/v1/jobs/:id/file` | Файл: `Range`, `ETag`, `X-Content-SHA256` |
| `GET /api/v1/jobs/:id/thumbnail` | Обложка jpeg ≤ 1280 px и ≤ 500 КБ, или `404 no_thumbnail` |
| `DELETE /api/v1/jobs/:id` | Отменить идущую или стереть готовую; всегда `204` |
| `GET /api/v1/health` | Версия yt-dlp и загрузка сервера |

Отличия от сайта:

- **Пределы на ключ**, а не на IP и куку: 2 задачи в работе, до 20 в очереди
  (дальше `503 queue_full`), 60 новых в час (`429 rate_limited`), оба
  с `Retry-After`. Сайт и API делят `MAX_CONCURRENT_DOWNLOADS`, но API берёт
  на одну меньше (`API_MAX_ACTIVE`) — посетителям сайта всегда остаётся место.
- **Проверка до скачивания**: yt-dlp сначала читает метаданные, и длинный
  ролик, большой файл, эфир, подборка или пост без видео отклоняются сразу.
  Пределы клиент присылает в запросе, сервис берёт меньшее из своих и его.
- **Файл по договору**: mp4, H.264 + AAC, `moov` в начале, высота не больше
  `maxHeight`. Чего у источника нет, то перекодирует ffmpeg (`veryfast`).
- **Хранение**: файл живёт час после готовности (у сайта — 5 минут), записи
  о задачах — сутки. Всё лежит на томе (`API_DATA_DIR`): после перезапуска
  клиент получает свою задачу, а прерванная загрузка начинается заново.
- **Машинные коды ошибок**: `{ "error": { code, message, retryable,
  retryAfterSec } }`. Сайт строит свой текст из того же кода.
- **Журнал** — JSON-строки в stdout с `requestId` из `X-Request-Id` клиента:
  поломку ищут по одному номеру на обеих сторонах. Секрет ключа, cookies
  и `Authorization` в журнал не попадают.
- CORS для `/api/v1` не включается: зовёт сервер, не браузер.

Проверка после выкладки:

```bash
curl -s -H "Authorization: Bearer $KEY" https://downloader.vr9.pro/api/v1/health
```

## Безопасность

Сервис принимает URL от анонимных пользователей, поэтому каждая ссылка проверяется
до запуска `yt-dlp`:

- хост должен быть в белом списке площадок: YouTube, Rutube, VK, TikTok,
  Instagram, Facebook, kino.pub (и CDN `cdntogo.net`) — посторонние адреса
  отклоняются с `400` до запуска `yt-dlp`
- только `http`/`https`, только порты 80 и 443 (`ALLOWED_PORTS`)
- запрещены ссылки с логином/паролем (`user:pass@host`)
- блокируются IP внутренней сети: `127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`,
  `169.254/16` (включая `169.254.169.254`), `100.64/10`, IPv6 ULA/link-local,
  а также обходы через десятичную/hex-нотацию и `::ffff:` маппинг
- имя хоста резолвится, и если хоть один адрес приватный — запрос отклоняется
- блокируются имена контейнеров (`mysql`) и внутренние зоны (`*.local`, `*.internal`)
- `ALLOWED_HOSTS` заменяет список площадок своим; `ALLOWED_HOSTS=*` снимает
  ограничение по хостам (проверки схемы, портов и приватных адресов остаются)
- CORS закрыт: API вызывается только со своего origin (`CORS_ORIGINS` — исключения)

Ограничения ресурсов (все настраиваются, см. `.env.template`):

| Что | Переменная | По умолчанию |
| --- | --- | --- |
| Стартов загрузки с IP | `RATE_LIMIT_DOWNLOAD_MAX` | 5 / 10 мин |
| Прочих запросов с IP | `RATE_LIMIT_API_MAX` | 240 / мин |
| Одновременных загрузок | `MAX_CONCURRENT_DOWNLOADS` | 3 |
| Одновременно с одного IP | `MAX_CONCURRENT_PER_CLIENT` | 1 |
| Размер одного файла | `MAX_DOWNLOAD_SIZE` | 4G |
| Всего временных файлов | `MAX_TOTAL_STORAGE` | 20G |
| Длительность видео | `MAX_DURATION_SECONDS` | 4 часа |
| Таймаут загрузки | `DOWNLOAD_TIMEOUT_MINUTES` | 30 мин |

Размер контролируется и «снаружи» yt-dlp: watchdog каждые 15 секунд считает объём
файлов загрузки и убивает процесс при превышении — это важно для HLS/m3u8,
где `--max-filesize` не работает, потому что размер заранее неизвестен.

За Traefik обязательно оставьте `TRUST_PROXY_HOPS=1`, иначе rate limit увидит
всех пользователей как один IP.

Cookies привязаны к площадке по имени хоста: ссылка на YouTube получает только
`cookiesYoutube.txt` (или общий `COOKIES_FILE`), kino.pub — только
`cookiesKinoPub.txt`, и так далее. Хост, не совпавший ни с одной площадкой,
не получает cookies вообще — включая общий файл и `--cookies-from-browser`.

Что осталось за пределами приложения: цепочку редиректов мы проверяем сами,
но `yt-dlp` ходит по ней повторно, а ссылку на манифест kino.pub берём со
страницы источника уже без DNS-проверки.

На практике это прикрыто белым списком: посторонний может прислать ссылку
только на площадки из списка, свой домен подставить не может. Поэтому запрет egress
из контейнера — **необязательная страховка, по умолчанию выключенная**. Включать
её стоит, если вы расширили `ALLOWED_HOSTS` (тем более до `*`) или во внутренней
сети сервера есть что-то чувствительное:

```bash
make firewall-status                          # проверить
sudo bash scripts/egress-firewall.sh          # применить вручную
sudo bash scripts/egress-firewall.sh --remove # откатить
```

Деплой правила не трогает: включать и выключать их нужно руками. Повторный
запуск безопасен — скрипт сверяется с текущим состоянием iptables и, если всё
на месте, пропускает шаг. Отметка о применении лежит в
`/var/lib/video-downloader/egress-firewall.state`, но решение принимается
по самим правилам: они слетают при перезагрузке, а docker при пересоздании сети
может выдать ей другую подсеть — файл-отметка в обоих случаях врал бы.

Все правила привязаны к подсети этого проекта, поэтому соседние контейнеры
в общей сети `traefik` под них не попадают. Скрипт трогает только свою цепочку
`VD-EGRESS` и уживается с ufw. После применения он проверяет, что исходящий
трафик контейнера действительно идёт через сеть сервиса — иначе правила были бы
привязаны не к той сети и молча не работали. Правила
iptables не переживают перезагрузку — чтобы возвращались сами, поставьте
systemd-юнит из шапки скрипта.
И помните, что публичный сервис использует ваши cookies kino.pub/YouTube
от вашего имени — если это нежелательно, уберите cookie-файлы.

## Частые проблемы

- `yt-dlp not found` — установи `yt-dlp` или задай `YTDLP_PATH`
- Ошибки авторизации — обнови cookies-файл/сессию в браузере
- **Часть видео не скачивается** — чаще всего устарел `yt-dlp` внутри образа.
  `make prod` и `make build` сбрасывают кеш слоя с `yt-dlp` датой сборки, так что
  каждый деплой ставит свежую nightly-версию, а `--pull` подтягивает свежий
  базовый образ. Версия — это дата релиза; сервер при старте предупреждает,
  если сборке больше 45 дней
- **Скачалось не то видео** — в логе на каждую загрузку есть строка `🎬` с id
  и названием того, что реально скачалось, а интерфейс показывает название
  рядом со ссылкой на файл. Карусели Instagram (`?img_index=N`) и истории
  из подборок (`?story_media_id=…`) выбираются по ссылке; без этих параметров
  берётся первый элемент поста
- **Скачивается только 360p** — YouTube не отдал качественные дорожки без
  PO Token. Проверьте в логах строку `PO Token:` при старте: контейнер
  `potprovider` должен отвечать
- `Requested format is not available` для YouTube — сервис сам повторяет попытку
  с другим `player_client`; при желании можно закрепить рабочий через
  `YT_PLAYER_CLIENT`
- **Файл не открывается или идёт без звука** — так бывает при `VIDEO_FORMAT=bv*+ba/b`:
  AV1/Opus внутри mp4 понимают не все плееры. Уберите переменную, чтобы вернуться
  к H.264 + AAC
- Ошибки сети — проверь `PROXY`/`YT_PROXY` и доступность сайта

## Важно

Используй только для контента, который тебе разрешено скачивать по закону и правилам источника.
